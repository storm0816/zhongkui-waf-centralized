# ZhongKui WAF 2.1.6 域名子名单验收

测试环境：

- Master：`10.15.108.11`
- Node：`10.15.108.69`
- 控制台：`http://10.15.108.11:1226`
- 项目目录：`/opt/openresty/zhongkui-waf`

## 一、先创建并发布 2.1.6 程序版本

1. 登录 Master 控制台。
2. 进入“集群与大屏 -> 发布中心 -> 程序版本”。
3. 点击“创建程序版本”。
4. 版本说明填写：`2.1.6 域名子黑白名单`。
5. 在 `2.1.6` 行点击“发布”，只选择 `10.15.108.69`。
6. 在“程序任务”中等待状态变成“成功”。

分别在 Master 和 Node 执行：

```bash
cd /opt/openresty/zhongkui-waf
grep APP_VERSION lib/constants.lua
/opt/openresty/nginx/sbin/nginx -t
```

预期两台服务器均显示 `2.1.6`，Nginx 检查成功。

## 二、选择测试域名

进入“防护策略 -> IP黑白名单”，从页面顶部选择一个测试站点，记录其中一个精确域名：

```bash
TEST_DOMAIN='替换为页面中的测试域名'
NODE_IP='10.15.108.69'
```

以下命令从 Master `10.15.108.11` 执行。Node 看到的来源 IP 应为 `10.15.108.11`。

先确认基础请求可以到达 Node：

```bash
curl -sS -o /dev/null -w 'HTTP %{http_code}\n' \
  -H "Host: $TEST_DOMAIN" \
  "http://$NODE_IP/__domain_policy_baseline__"
```

记录返回码，后续与命中结果比较。

## 三、测试域名子黑名单

在“域名子黑白名单”中新增：

```text
精确域名：测试域名
规则类型：子黑名单
IP / 网段：10.15.108.11
备注：2.1.6 子黑名单测试
状态：启用
```

保存后等待约 40 秒，再从 Master 执行：

```bash
curl -i -sS \
  -H "Host: $TEST_DOMAIN" \
  "http://$NODE_IP/__domain_policy_black_test__" | head -n 20
```

预期结果：

- 请求执行黑名单处置动作，返回码、重定向或响应内容与未加规则前不同。
- WAF 日志中能看到 `blackip` 或对应黑名单命中记录。

Node 查看日志：

```bash
grep -R "10.15.108.11" /opt/openresty/nginx/logs/hack/ | tail -n 20
```

## 四、测试精确域名隔离

选择同一 Node 上另一个未配置该子规则的域名：

```bash
OTHER_DOMAIN='替换为另一个域名'
curl -i -sS \
  -H "Host: $OTHER_DOMAIN" \
  "http://$NODE_IP/__domain_policy_other_domain__" | head -n 20
```

预期结果：该请求不应因为 `TEST_DOMAIN` 的子黑名单而被拦截。

这一步用于证明规则按请求 Host 精确隔离，而不是按整个站点或整个 Node 生效。

## 五、测试域名子白名单

先删除第三章的子黑名单，或者将其状态改为停用，然后新增：

```text
精确域名：测试域名
规则类型：子白名单
IP / 网段：10.15.108.11
备注：2.1.6 子白名单测试
状态：启用
```

等待约 40 秒后执行一个通常会进入 WAF 检测的请求：

```bash
curl -i -sS \
  -H "Host: $TEST_DOMAIN" \
  "http://$NODE_IP/.git/config" | head -n 20
```

预期结果：来源 IP 命中该域名子白名单，请求不会继续进入后续攻击检测。

再使用其他域名请求相同路径：

```bash
curl -i -sS \
  -H "Host: $OTHER_DOMAIN" \
  "http://$NODE_IP/.git/config" | head -n 20
```

预期结果：其他域名不会继承 `TEST_DOMAIN` 的子白名单。

## 六、测试地域子黑名单

先删除或停用子白名单，避免白名单优先放行。新增：

```text
精确域名：测试域名
规则类型：地域子黑名单
国家/地区：美国 (US)
备注：2.1.6 地域子黑名单测试
状态：启用
```

等待约 40 秒后，从 Master 模拟一个美国公网来源：

```bash
curl -i -sS \
  -H "Host: $TEST_DOMAIN" \
  -H 'X-Forwarded-For: 8.8.8.8' \
  "http://$NODE_IP/__domain_policy_region_test__" | head -n 20
```

预期结果：`8.8.8.8` 经 GeoIP 查询为 `US`，请求执行黑名单处置动作。

验证跨域隔离：

```bash
curl -i -sS \
  -H "Host: $OTHER_DOMAIN" \
  -H 'X-Forwarded-For: 8.8.8.8' \
  "http://$NODE_IP/__domain_policy_region_other__" | head -n 20
```

预期结果：其他域名不会因为 `TEST_DOMAIN` 的 `US` 规则被拦截。

> `X-Forwarded-For` 仅适合在当前测试环境模拟来源地址。生产环境应限制哪些上游代理有权传递该请求头。

## 七、验证 MySQL -> Redis -> Node 同步

### 1. Master 本地候选文件

```bash
cd /opt/openresty/zhongkui-waf
jq . conf/global_rules/domainIpPolicy.json
```

预期能看到刚刚保存的域名子规则。

### 2. Redis 已发布快照

在 Master 执行，命令从 `system.json` 读取 Redis 地址和密码，不会将密码写入命令行参数：

```bash
cd /opt/openresty/zhongkui-waf
CFG=conf/system.json
REDIS_HOST=$(jq -r '.redis.host' "$CFG")
REDIS_PORT=$(jq -r '.redis.port' "$CFG")
REDIS_DB=$(jq -r '.redis.db' "$CFG")
export REDISCLI_AUTH=$(jq -r '.redis.password' "$CFG")

/opt/redis16381/redis-cli -h "$REDIS_HOST" -p "$REDIS_PORT" -n "$REDIS_DB" \
  GET waf:cluster:rules:snapshot | jq '.ip_groups.domain_policies'
```

预期 Redis 快照中能看到相同规则。

### 3. Node 最后可用快照

在 Node 执行：

```bash
cd /opt/openresty/zhongkui-waf
jq '.ip_groups.domain_policies' conf/.cluster/rules-lkg.json
jq -r '.version' conf/.cluster/rules-lkg.json
```

预期 Node 快照包含相同规则，并且版本不为空。

### 4. 对比 Redis 和 Node 规则版本

Master 执行：

```bash
/opt/redis16381/redis-cli -h "$REDIS_HOST" -p "$REDIS_PORT" -n "$REDIS_DB" \
  GET waf:cluster:rules:snapshot:version
```

将结果与 Node `rules-lkg.json` 的 `version` 对比，二者应完全一致。

## 八、测试停用与删除

1. 编辑测试规则，将状态改为“停用”。
2. 等待 Node 同步，再重复对应请求，规则应不再命中。
3. 删除测试规则。
4. 确认页面、Master 文件、Redis 快照和 Node LKG 快照中都不再存在该规则。

快速查询测试备注：

```bash
grep -R "2.1.6 .*测试" /opt/openresty/zhongkui-waf/conf/global_rules/domainIpPolicy.json || true
```

## 九、检查服务错误

Master 和 Node 分别执行：

```bash
/opt/openresty/nginx/sbin/nginx -t
tail -n 300 /opt/openresty/nginx/logs/error.log | \
  grep -E '\[error\]|domain.*policy|invalid.*domain|snapshot' | tail -n 50
```

验收期间不应出现新的规则解析、快照校验或 Lua 运行错误。

## 十、验收标准

- 全局名单原有行为不变。
- 子白名单只对配置的精确域名生效。
- 子黑名单只对配置的精确域名生效。
- 地域子黑名单按 MMDB 原始国家/地区代码生效。
- 停用规则立即退出下一次发布快照。
- 删除规则后 Master、Redis 和 Node 均不再保留该规则。
- MySQL 发布成功后 Redis 才更新，Node 只加载通过哈希校验的快照。
- Node 与 Redis 规则版本一致。
- `system.json`、证书、日志及 GeoIP 文件未被规则发布覆盖。

## 十一、回滚方法

功能级回滚优先使用页面删除或停用域名子规则，保存后会生成新的权威快照并同步 Node。

需要回滚程序时：

1. 进入“发布中心 -> 程序版本”。
2. 找到已保留的 `2.1.5` 快照。
3. 点击“发布”，选择需要回滚的 Node。
4. 在“程序任务”中等待成功。

注意：回滚 Node 程序不会自动删除 MySQL 中的 2.1.6 规则快照。再次升级到 2.1.6 后，子规则仍会恢复；若不再需要，必须先在页面停用或删除。
