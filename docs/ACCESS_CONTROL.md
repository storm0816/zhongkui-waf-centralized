# 管理台账号、LDAP 与 MFA

## 默认权限模型

系统首次使用时会自动创建账号与权限表，并保留原有本地 `admin` 作为应急管理员。

| 内置角色 | 权限 | 用途 |
| --- | --- | --- |
| `super_admin` | 只读、管理、用户管理 | 完整管理权限 |
| `manager` | 只读、管理 | 管理 WAF 配置，不能维护账号 |
| `readonly` | 只读 | 查看配置、日志和报表 |

管理路径：`基础配置 -> 用户与权限`。系统会阻止禁用最后一个超级管理员，或移除其超级管理员角色。

## LDAP 设置

在 `基础配置 -> 系统设置 -> LDAP 登录` 中填写：

LDAP 与 MySQL、Redis 使用同一个 `conf/system.json`，不需要单独的 LDAP 配置文件。Master、Node 和完整包模板均包含相同的 LDAP 配置段。

- 主服务器和备服务器，例如 `ldap://10.10.10.10:389`。
- AD 推荐配置连接账号、连接密码、查询基准和用户属性（通常为 `sAMAccountName`）。系统先用连接账号查询用户 DN，再使用登录用户自己的密码完成二次绑定。
- LDAP 支持直接账号绑定时，绑定格式填写 `%s`。
- LDAP 要求完整 DN 时，填写类似 `uid=%s,ou=people,dc=example,dc=com`。
- 生产环境优先使用 `ldaps://...:636`，或在 389 端口开启 StartTLS，避免密码明文传输。
- 使用 LDAPS 或 StartTLS 时建议开启证书验证，并确保 OpenResty 主机信任 LDAP CA。

LDAP 登录用户的密码只用于当次二次绑定验证，不写入配置、数据库或日志。LDAP 连接密码保存在服务器的 `system.json` 中，但不会通过管理接口回显。LDAP 用户首次成功登录后会自动建立本地映射，并默认分配 `readonly` 角色；管理员也可以提前创建用户并指定角色。

## MFA

在 `基础配置 -> 系统设置 -> 登录安全` 中可开启“所有用户强制 MFA”。开启后，未绑定用户下次登录会显示 TOTP 密钥和 URI，使用常见身份验证器添加后输入 6 位动态码完成绑定。

MFA 密钥使用系统密钥加密后存入 MySQL。修改系统密钥会导致已绑定的 MFA 无法解密，因此启用 MFA 后不要直接更换系统密钥。

## 会话与审计

- 登录会话保存在 Redis，默认 30 分钟滑动过期。
- 账号被禁用或角色权限变化后，已有会话在下一次请求立即按最新状态校验。
- 连续登录失败会按来源 IP 和用户名限制 5 分钟。
- 用户、角色和权限变更记录在管理审计日志中。
