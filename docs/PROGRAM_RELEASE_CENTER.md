# 程序发布中心

## 定位

程序发布中心负责 Master 与 Node 的程序版本一致性。规则、白名单、黑名单、CC 和敏感数据规则仍由现有 MySQL、Redis 发布链路负责。

2.1.4 是自动发布功能的基线版本。已有 Master 和 Node 必须先通过 `upgrade.sh` 升级到 2.1.4，后续版本才可从发布中心自动升级。

## 发布流程

1. Master 完成新版本代码升级和验证。
2. 超级管理员在“集群与大屏 → 发布中心”创建当前版本快照。
3. 系统将程序文件复制到 `/opt/openresty/zhongkui-program-releases/<version>`，并生成 SHA-256 文件清单。
4. 管理员选择目标 Node，并设置灰度节点、批次大小和批次间隔。
5. 灰度模式先只下发 1 台；灰度成功后，系统才会继续后续批次，失败时自动暂停。
6. 普通批次等待上一批结束，并达到批次间隔后再写入 Redis，避免全部 Node 同时下载。
7. Node 从 Master 的内网 HTTP 下载接口拉取文件，在临时目录完成下载和逐文件校验。
8. Node 备份当前目录后执行原子切换；`nginx -t` 或重载失败时自动恢复旧程序目录。
9. Node 通过心跳回报目标版本、批次、执行状态和错误信息，Master 页面展示结果。

发布计划保存在 MySQL，Master 重启后会继续推进。批次大小允许 `1~50` 台，批次间隔允许 `30~3600` 秒；默认灰度发布、每批 2 台、间隔 60 秒。

## 文件边界

自动发布包含 Lua 程序、管理端前后端、HTML、WAF 公共文件和更新脚本。

以下内容不会进入程序快照，也不会被自动发布覆盖：

- `conf/system.json` 与角色模板
- 运行规则和站点配置
- 管理员账户数据
- 证书、私钥、日志和缓存
- 安装依赖压缩包与 MMDB 数据库

## 权限

- `read`：查看版本和发布状态。
- `release.manage`：创建版本、发布、重试和回滚。
- 内置 `super_admin` 自动获得 `release.manage`。

## 回滚

历史版本快照保持不可变。选择历史版本重新发布到目标 Node，即执行版本回滚。Node 本地也会保留切换前的备份，切换校验失败时自动恢复。
